# 항구의 트레이지아 (港のトレイジア) 한글화 패치

텔레네트 재팬 1991년작 메가드라이브 RPG **항구의 트레이지아(Minato no Traysia)** 의 한글화 패치입니다.

> 🚧 **v0.6 — 개발 중** — 미해결로 남아 있던 **예/아니오 선택지와 타이틀 로고**를 해결했습니다.
> 둘 다 텍스트가 아니라 **스프라이트 그래픽**이었습니다.

## 기술 개요

- **텍스트 인코딩** — Shift-JIS 기반이지만 **청음 히라가나·구두점은 1바이트**(0xA0~0xDD)로
  저장되고 탁음·카타카나·한자만 전각 2바이트입니다. 렌더러가 표 `0x1898`(62엔트리)로
  전각 변환합니다. 전각쌍만 훑으면 NPC 대사 대부분을 놓칩니다.
- **폰트** — `0xE0000`, **12×12 1bpp, 글리프당 18바이트**(행 경계 없이 12비트씩 팩킹).
  JIS 제1+2수준 7,281자가 들어 있습니다.
- **한글화 방식** — 렌더러 훅 없이 **원본이 안 쓰는 한자 슬롯에 한글 글리프를 심고**
  번역문에 해당 SJIS 코드를 씁니다. 글리프 인덱스가 0xAA 이상이라 폭이 자동으로 12px 고정됩니다.
  글꼴은 굴림 12px.
- **슬롯 제약** — 인덱스 계산(`0x1636`)의 `andi.w #$1F7F` 때문에 **도달 가능한 인덱스는
  339~3346뿐**입니다. 폰트에 실재하는 제2수준(3347~)은 렌더러가 가리키지 못합니다.
  번역으로 덮인 자리의 한자는 슬롯을 회수하도록 해서, 번역이 늘수록 예산도 함께 늘어납니다.
- **번역은 in-place** — 원문 바이트 길이를 넘길 수 없습니다. 원문 히라가나가 1바이트인데
  한글은 2바이트라 문장을 상당히 압축해야 합니다.
- **일부 UI는 텍스트가 아니라 스프라이트** — 예/아니오 선택지와 타이틀 로고는 평문·폰트
  어디에도 없어 오래 막혀 있었습니다. 세이브스테이트의 VRAM을 떠 스프라이트 테이블을
  역추적해서 찾았습니다.
  - 예/아니오: LZSS 소스 `0xDA914` → VRAM `0xB000` (32타일). 프레임·커서는 두고 글자만 교체
  - 타이틀 로고: LZSS 소스 `0x867F2` → VRAM 타일 `0x487~`, 배치는 기술 테이블 `0x7DB10`
    (8B/엔트리, size의 bit15가 목록 종료). 스프라이트 구성을 한글 자수에 맞춰 다시 짰습니다

## 변경 이력

### v0.6 (2026-07-30) — 개발 중
- **예/아니오 선택지 한글화**. 텍스트가 아니라 4bpp 스프라이트 그래픽이었음
  (LZSS `0xDA914` → VRAM `0xB000`). 프레임·커서는 원본 유지하고 글자만 「예」/「아니오」로 교체
- **타이틀 로고 한글화**. 「항구의」는 작게, 「트레이지아」는 크게, 셰리프체(HY태백B)로
  원본과 같은 색 구성(밝은 노랑 + 우하 그림자). 스프라이트 기술 테이블 `0x7DB10` 을
  16개 스프라이트/149타일로 재작성
- LZSS 압축기 버그 수정 — 겹침 복사 시 링버퍼에 방금 쓴 값을 다시 읽는 동작을
  모델링하지 않아 재압축 결과가 깨졌음(로고 하단 줄이 어긋남). 미기록 링 위치 참조도 차단

### v0.5 (2026-07-30)
- **몬스터 이름 99종 번역**. 레코드 구조 `[이름(가변, 0x00 종료)][데이터 75B]` 를 확인하고
  원본 바이트 길이를 지켜 in-place 교체(레코드 무손상 검증 완료)

### v0.4 (2026-07-29)
- 인게임 검증 반영. 추출기의 **구조적 누락 3건**을 수정하고 297곳을 추가 번역
  - `々`(U+3005) 등 기호가 문자 판정에서 빠져 그 글자가 든 대사가 통째로 탈락
  - 본문에 섞인 ASCII(공백·영문)가 판정에서 빠져 같은 문제 발생
  - 번역 길이를 런 전체로 잡아 뒷문장을 덮어써 바이트가 어긋남(여관 「＆」 깨짐)
- 전투용 이름 테이블(0x21EC8~) 별도 발견·번역, 스태프롤 번역
- 한글 글리프 794자, 길이 초과 0건, 슬롯 충돌 0건
